## 二、N-1 修复核对

**合约**：`post` 和 `postCatchUp` 共用同一套检查（运营地址、0 < 买一 ≤ 卖一、间隔 ≥ 50 分钟、每次 ±5%），区别只在 `catchingUp` 标志；`fresh()` 在追价期间返回假。逐个核对追价期间各处的行为：

| 位置 | 追价期间的行为 | 结论 |
|---|---|---|
| 两种局收购（`buyQuote`） | 返回 0，`sellMachine` 回滚 `PriceUnavailable`；MarketTrader 代买、月局交接也随之回滚 | ✅ 暂停 |
| 标准局市价期卖出（`sellQuote`） | 返回 0，`buyMachine` 回滚 `NotForSale` | ✅ 暂停 |
| 月局卖出（`askPrice`） | 没有停运，按报价算的价格为 0，**不会**退到成本价 | ✅ 暂停 |
| 月局清算计划价 | 要求报价有效，追价期间为 0 | ✅ 暂停 |
| 外部市场上已挂着的单（MachineLister） | 买家成交时结算拿到的要价为 0，整笔回滚 `NotForSale`；任何人可以撤回寄售 | ✅ 不会低价成交 |
| 停运判断（`abandoned`） | 按最后一次报价时间算，追价期间不触发 | ✅ 符合设计（但见 N-2） |

**机器人**：`postFunction` 只有在买一、卖一都正好等于目标价时才用 `post`，其余一律用 `postCatchUp`，偏保守，没有问题；追价时会发 Telegram 提醒；有对应单元测试。

**项目回归测试**：`test_N1_CatchUpPausesTradingUntilTheLastStep`（追价 6 步期间收购价为 0，最后一步后按市价恢复）和 `test_N1_CatchUpLimitsAndMonthSalesPaused`（追价也受 ±5% 限制、月局暂停而不是按成本价）都通过。

**附带影响**（无需修改，供知悉）：
- 标准局进入降价拍卖的那一刻如果正在追价，拍卖起价按"采购均价 × 150%"快照，而不是按买一。起价偏高，但 14 天内会降到底价，不会造成损失。
- "保持排序第一"的目标价不受追价影响，只在标准局降价拍卖阶段起作用，最多让价格降 5%，且不低于成本，和平时一样。
- 如果追价恰好覆盖了标准局首轮收购期（7 天）或月局准备期（3 天），这段时间买不到矿机，主板会按规则退款或原样退还资金。不会亏钱，但这一局白开了。行情大跳时机器人的提醒能让运营及时处理。

## 三、新问题 N-2（低）：追价可以无限延长暂停，跳过停运兜底

**位置**：`src/MarketPriceFeed.sol` `abandoned()`、`_post()`。

**问题**：`abandoned()` 按最后一次报价时间判断，而 `postCatchUp` 每次都会刷新这个时间。运营地址只要每 50 分钟报一次 `postCatchUp`（价格在 5% 内来回），报价就一直不新鲜、也永远不会被判为停运：
- 月局：卖不出矿机，也到不了"7 天后按成本价可买"的兜底，本金一直锁在矿机里；多数清算计划也无法成交；
- 两种局的收购一直暂停；标准局市价期暂停（30 天后的降价拍卖不依赖报价，照常进行）。

`AUDIT.md` 第 27 节说"追价只会暂停交易，而不报价本来就能做到"。这句话不完全准确：不报价 7 天后会进入停运兜底，一直追价则不会。

**复现测试**（`AuditRecheck2.t.sol`）：
- `test_N2_NoPostingReachesCostFallback`（对照）：运营地址不报价，7 天后停运，月局按成本价可买；
- `test_N2_EndlessCatchUpBlocksCostFallback`：运营地址连续 8 天每 50 分钟报一次 `postCatchUp`，仍然不算停运，月局要价一直为 0。手续费 Safe 把运营地址设成 0 后，7 天后兜底恢复。

**影响评估**：前提是运营私钥被盗或运营方作恶，而且手续费 Safe 一直不处理。不会直接亏钱，最坏是资金长期卡住；Safe 换掉运营地址即可恢复，所以定为低风险。

**建议修法**：停运改按"最后一次**有效**报价"（`post`，或第一次报价）的时间计算。我在临时副本里试过，全量测试（含本次 2 个复核测试）384 个通过、合约体积检查通过：

```diff
     bool public catchingUp;
+    /// @notice 最近一次有效报价（post，或第一次报价）的时间；停运按它算，追价再久也会停运
+    uint256 public liveAt;
 ...
         catchingUp = catchUp;
+        if (!catchUp || t == 0) liveAt = block.timestamp;
 ...
     function abandoned() public view returns (bool) {
-        uint256 t = updatedAt;
-        return t == 0 || block.timestamp >= t + abandonAfter;
+        return updatedAt == 0 || block.timestamp >= liveAt + abandonAfter;
     }
```

配套修改：
1. 测试里直接写报价存储的三个辅助函数也要写 `liveAt`（存储槽 6），否则相关测试会误判为停运：`test/utils/Fixture.sol` 的 `_forcePrices`、`test/E2EForkBSC.t.sol` 和 `test/probe/MarketModulesFork.t.sol` 的 `_forceFeed`。
2. `AuditRecheck2.t.sol` 里 N-2 那条测试改成断言"8 天后停运、月局按成本价可买"（副本里改后已通过）。
3. 正常追价最多几个小时（跌 30% 约 6 小时，报错 100 倍约 3 天），离 7 天还很远，这个修法不会影响正常追价。
4. 更新 `AUDIT.md` 第 27 节和规则决定，改正上面那句措辞。

如果不改代码：把 N-2 写进 `AUDIT.md` 第 7 节已知问题（"被盗的运营地址可以一直追价，让交易长期暂停，需由手续费 Safe 更换运营地址"），并在应急手册里写明：长时间处于追价状态（例如超过 12 小时）就按私钥被盗处理。机器人的 `feed:catchup` 提醒可以作为监控信号。
