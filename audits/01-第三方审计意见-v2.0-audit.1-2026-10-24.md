## 一、整体审计意见

**结论：现在的代码不建议直接上主网。先修完下文的 2 个高风险和 4 个中风险问题，再交给专业审计公司做正式审计。**

代码整体质量好：已开局的主板没有任何管理员和升级入口，资金记账用累加器、守恒有模糊测试，所有外部入口都有重入锁，收款都核对实际到账，外部市场成交在同一笔交易里按公式价结算，VRF 回调失败不会卡死主板。我**没有发现**外部攻击者不借助任何特权、直接偷走主板资金的典型漏洞（重入、权限缺失、记账错误、整数溢出、回调伪造等都核对过）。

但下面两类问题会让参与者真实亏钱：

1. **运营地址的定价权比文档写的大得多（H-1）**。文档说报价"每次最多变 5%"，实际只要停报 3 小时，下一次就可以报任意价格。运营私钥放在机器人服务器上，一旦被盗，攻击者可以让所有正在收购的主板按"一年产出"的上限价买矿机。复现测试里，一块 500 BEM 的标准局，一台矿机就多付了 **329 BEM**。
2. **月局多数清算没有价格下限（H-2）**。过半持仓可以通过一个"按 1 wei 卖矿机"的计划，再自己把矿机买走。复现测试里，少数派 48 BEM 本金最后只能领回 **12.44 BEM**。加入只限"一个地址一份"，开小号的成本很低（每张通行证约 0.0057 BNB），这个攻击现实可行。

另外，TapeOut 升级一次电路合约后，之后新开的每一局都能被**任何一个**持有人单方面提前终局（M-1）；标准局盘口的"通用买单"会被已经拿走 105% 的出局持仓成交（M-2）。这两项影响游戏公平。

## 二、问题详情

### H-1（高）报价限幅在停报 3 小时后失效

**位置**：`src/MarketPriceFeed.sol` 第 87–92 行 `post()`；相关：`postFloor()` 第 103–109 行、`StdMachineSales._price`、`MonthMachineSales.askPrice`。

**问题**：
```solidity
if (block.timestamp < t + maxStaleness && (!_within(newBid, lastBid) || !_within(newAsk, lastAsk))) {
    revert ChangeTooLarge();
}
```
±5% 的限制只在"上一次报价还没过期（3 小时内）"时检查。停报满 3 小时后，下一次可以报任意 bid / ask。即使不停报，5% / 50 分钟复利一天也能把价格推高约 4 倍。`postFloor`（保持排序第一的目标价）完全没有频率和幅度限制。

`AUDIT.md` 第 3、5.8 节和已知问题 K10 把"5% / 50 分钟"当作运营定价权的边界，这个边界实际不存在。

**影响**（运营私钥被盗或运营方作恶）：
- **收购端**：报高 ask / bid → 收购价 = 上限（一年产出，绝对上限 3 BEM / 单位算力）。任何人都能在外部市场按真实价格买矿机、同一笔交易按上限卖给主板。复现测试 PoC-1：500 BEM 标准局，假设真实市价为上限的 1/3，一台 300 算力矿机付了 493.95 BEM，按市价只值 164.65 BEM，**多付 329.30 BEM**。同一时间所有正在收购的标准局和月局都会被套利。
- **卖出端**：标准局市价期按底价（采购均价 60%）卖出，降价拍卖的起价快照也能被压到底价；月局用 `postFloor` 把卖价压到正好成本价，参与者失去全部溢价。

**建议**：
1. `post()` 去掉"上次过期就不限幅"的例外，任何时候单次变动都 ≤ 5%。
2. 行情真的大幅跳空时，走"大幅改价待生效"：超过 5% 的新价先挂起 N 小时（例如 6 小时），期间 `fresh()` 返回 false（暂停按报价买卖），手续费 Safe 可以撤销。这样被盗私钥无法在一个区块内完成攻击，Safe 有时间反应。
3. `postFloor` 也加频率和幅度限制，或只允许在 `[成本, 公式价]` 中更靠近公式价的一侧（例如不低于公式价的 95%）。
4. 报价私钥和执行开奖 / 发放的运营私钥分开（见 O-1）。

### H-2（高）月局多数清算计划没有价格下限

**位置**：`src/month/MonthExitGovernor.sol` 第 137–161 行 `publishPlan`（只要求底价 > 0）；`src/month/MonthMachineSales.sol` 第 101–133 行 `askPrice` / `planAsk`；`src/MonthBoard.sol` 第 781 行（`liquidating` 为真时不再检查成本价）。

**问题**：计划价可以低到 1 wei，计划执行后任何人都能按计划价买走矿机。通过条件是"赞成 > 全部本金的一半"。投票和执行等待期间全局锁定转让，少数派没法先卖持仓离场。

**攻击路径**：开 13 个小号（每个带一张约 0.0057 BNB 的通行证）各投 4% 拿到 52%，或在结算期从盘口收持仓 → 结算满 7 天发布"起价 = 底价 = 1 wei"的计划 → 3 个小号支持开启投票 → 24 小时投票 + 24 小时等待 → 执行后同一区块按 1 wei 一台买走全部矿机。

**复现测试 PoC-2**：25 份 × 4 BEM 的月局，矿机成本合计 74.09 BEM。攻击者用 3 wei 买走全部 3 台矿机；少数派 12 份（48 BEM 本金）全部投反对，最后只能领回 12.44 BEM，**损失约 74%**。

**建议**（选一种或组合）：
1. **计划价不低于市场价**：成交时计划价取 `max(计划价, 当时买一 × 算力 × 95%)`；报价不新鲜时暂停计划价成交。这样多数派只能"接受市价止损"，不能低于市价甩卖给自己。示意：
   ```solidity
   // MonthMachineSales.askPrice
   uint256 p = planAsk(board, index);
   if (p > 0) {
       if (!feed.fresh()) return 0;
       uint256 marketFloor = feed.bid() * m.weight * 9_500 / 10_000;
       if (p < marketFloor) p = marketFloor;
       if (price == 0 || p < price) price = p;
   }
   ```
   （这一条依赖 H-1 先修好，否则运营地址能压低买一。）
2. `publishPlan` 要求每台的起价 ≥ 成本价，保证计划是真正的降价拍卖，而不是开盘即底价。
3. 至少在白皮书、dApp 和规则文档里明确告知：月局过半持仓可以决定低于市价出售。

### M-1（中）升级哨兵触发后永久有效

**位置**：`src/TapeBoard.sol` 第 701–707 行 `emergencyExit`；`src/MonthBoard.sol` 第 662–671 行 `emergencySettle`；`sentinelTripped()` 和模板部署时记下的 `MACHINE_IMPL_AT_DEPLOY` 比较（immutable，所有克隆共用）。

**问题**：TapeOut 只要升级一次电路合约的信标（这是项目方控制不了的例行操作），`sentinelTripped()` 就永远为真。30 天冷静期结束后工厂照常开新局，而这些新局：
- 标准局：**任何一个**未出局持有人（哪怕只投了 0.2%）都能 `emergencyExit`，全局按保底公式结束（没有硅王奖、后续出局 105% 全部取消）；
- 月局：挖矿期内**任何一个**持有人都能 `emergencySettle`，取消开奖、奖金池按比例分。

`AUDIT.md` 第 3 节写的是"冷静期内"才能提前退出，代码没有这个限制。复现测试 PoC-3：信标升级、登记、过 30 天后，新开的标准局和月局都被一个持有人单方面结束。

**建议**：
1. 两个函数都改成只在冷静期内可用：`if (!sentinelPaused()) revert ...`（替换现在的 `sentinelTripped()` 检查，字节数基本不变）。
2. 运维上准备好"TapeOut 升级后 → 核对新实现 → 走 7 天时间锁换模板"的流程，让新模板记录新的实现地址。

### M-2（中）标准局通用买单不区分出局 / 未出局持仓

**位置**：`src/month/PositionExchange.sol` 第 290–343 行 `placeBid` / `sellToBid`。

**问题**：买单是"本局任何一份大小在范围内的持仓都能卖给它"，不记局交易版本号，也不看持仓是否已出局。标准局里未出局持仓（还能拿 105% 或硅王奖）和已出局持仓（只剩底池份额）价值相差很大。每次开奖后，刚出局的人可以立刻把持仓卖给之前按"在局"定价挂着的买单。

**复现测试 PoC-4**：第 5 号出局，当场拿到 21 BEM（105%），随后把这份已兑现的持仓按 20 BEM 卖给了买单。

**建议**：
1. 标准局买单记录挂单时的 `tradeEpoch`，`sellToBid` 时不一致就拒绝（每次出局、进入终局后买单自动失效，买家需要重挂）；
2. 或者给买单加"只收未出局 / 只收已出局"选项，`sellToBid` 检查 `socket.ejected`；
3. 至少在 dApp 下买单时明确提示。

### M-3（中）VRF 重新请求可被用来"重抽"

**位置**：`TapeBoard.retryDraw` 第 675–680 行、`MonthBoard.retryDraw` 第 647–652 行；两边的 `onRandomness` 只接受最新的请求编号。

**问题**：请求超过 24 小时没回调，运营地址可以重发，旧请求作废。VRF 订阅归项目方个人钱包（`AUDIT.md` 第 4 节），运营地址也是项目方。可行的路径：订阅余额不足 → 请求挂起超过 24 小时 → 充值 → Chainlink 节点提交回调交易 → 从交易数据里能算出随机数 → 结果不满意时抢先 `retryDraw`，回调变成过期被忽略。订阅所有者也可以直接取消订阅，7 天后正在等开奖的标准局可以进入安全退出、月局不开奖直接按比例分（都会改变分配结果）。

**建议**：
1. 改成"同一轮开奖发出的所有请求都有效，先到先用"：给每个请求记开奖轮次，`onRandomness` 只要轮次匹配且还在等待就接受。重发只增加送达机会，不能作废已在路上的结果。注意 `TapeBoard` 只剩约 481 字节，改动要做体积检查。
2. VRF 订阅所有权转给多签 Safe，并公开订阅号和余额监控。

### M-4（中）把运营地址设成 0 会让结算中的月局立刻按成本价被买走

**位置**：`src/MarketPriceFeed.sol` 第 127–130 行 `abandoned()`、第 137–139 行 `buyQuote()`；`MonthMachineSales.askPrice` 第 107–108 行。

**问题**：`abandoned()` 在运营地址为 0 时立即返回真，月局卖价立刻变成成本价。如果手续费 Safe 发现运营私钥被盗，最自然的反应是 `setOperator(0)`，但这一步会让所有结算中的月局按成本价被套利者买空（市价高于成本时，参与者失去全部溢价）。同时收购端回到默认曲线（最高到一年产出）。

**建议**：
1. `abandoned()` 只按时间判断（7 天没报价），不因运营地址为 0 立刻成立；运营地址为 0 时 `fresh()` 为假即可（暂停按报价买卖）。
2. 运维规则：**不要用 `setOperator(0)` 当紧急刹车**，应换成一个新的、安全的运营地址。

### L-1（低）矿机撤回后，往旧挂单库打 BNB 会把矿机卡死在 MachineLister

**位置**：`src/market/MachineLister.sol` 第 323–346 行 `onProceeds`。

**问题**：`onProceeds` 只检查"矿机不在挂单库"，没检查"矿机回到了主板"。撤回后挂单库的登记不会清除，任何人往它打 BNB 都会触发结算：卖矿合约看到矿机在主板，就把矿机转给调用者 MachineLister，而 MachineLister 没有任何转出入口。主板按公式价收了钱不会亏，但打款人损失 BNB，矿机永久卡死（例如有人误把 BNB 打到挂单库地址）。复现测试 PoC-5 已确认。

**建议**：`onProceeds` 里加 `if (IERC721(collection).ownerOf(id) == board) revert NotSold();`，或者撤回时清除挂单库的寄售状态。

### L-2（低）外部市场成交时，最后一次领取之后的挖矿产出归买家

**位置**：`MachineLister.onProceeds` → 卖矿合约 → 主板 `releaseMachine` 里的 `_claimOne`。市场先把矿机交给买家再付款，主板领取时 PoD 把这段产出付给了新持有人。直接按公式价购买的路径没有这个问题。

**建议**：机器人在挂单和改价前、以及定时调用 `harvest`，把差额压到很小即可。

### L-3（低）2% 滑点空间可被夹子机器人吃掉

**位置**：`MachineLister.prices`（挂单价 = 要价 ÷ 98%）、`onProceeds` 的兑换下限（TWAP × 98%）、`MarketTrader._buy`（最多多付 2%）、`GenesisSplitter._swap`。夹子机器人可以在不触发回滚的前提下吃掉"多出来的部分"（扣掉池子手续费约 1%）。

**建议**：机器人交易走私有交易通道；主网观察实际滑点后考虑收紧到 1.5%。

### L-4（低）TWAP 观测容量与出块速度

**位置**：`src/oracle/PancakeV3TwapOracle.sol`。BEM/USDT 池观测容量 2,048，项目文档按 BSC 每块约 0.75 秒计算。如果这个池子每个区块都有成交，2,048 个观测只覆盖约 25.6 分钟，不到 30 分钟窗口，`observe` 会回滚，分账回购、MarketTrader、MachineLister 的兑换全部暂停（不会亏钱，但会停摆）。WBNB/USDT 池（4,500）在出块进一步加快时也接近边界。

**建议**：上线前任何人都可以对两个池子调用 `increaseObservationCardinalityNext`，把容量提到能覆盖 2 倍窗口（例如 BEM 池 ≥ 5,000、WBNB 池 ≥ 8,000），并加监控。

### L-5（低）收购上限快照时点任何人可选（已知 K2）

报价有效时收购价不超过运营报的卖一，上限只在"从没报价 / 运营地址为 0"的默认曲线下起作用，所以实际风险低。修完 M-4 后进一步降低。维持"已知、接受"即可。

### L-6（低）治理开启投票可反复锁定转让

持有 10% 支持的人可以每 14 天（失败冷却期）开启一次投票，锁定全局转让 24 小时，盘口卖单全部失效。建议把失败冷却期按同一批支持者递增，或要求开启投票时有更高门槛。

### 信息类

- **I-1 新模板的权限范围**：模板经 7 天时间锁生效后，新开的局可以调用 `MonthFactory.onBoardStarted` 拿走工厂里全部滚存 BEM、在注册中心登记回馈名次、使用持仓凭证和 VRF 订阅。只影响之后的新局和项目自己的回馈资金，但用户需要知道"手续费 Safe 可以换新局的代码"。建议 dApp 显示每局用的模板版本，新模板提议时公开源码和差异。
- **I-2 两局之间的价差**：同一份报价下，收购价最高可到卖一，卖价从卖一 × 99% 往下降，正在准备的月局可能按卖一买入正在卖出的局按更低价卖出的矿机，差价被搬运者拿走。交接（relay）功能可以优先使用。
- **I-3 领取期满销毁**：365 天后 `closeClaims` 销毁合约里全部 BEM，包括记在基金会和手续费 Safe 名下、没领走的款项。运维上要定期提取。
- **I-4 外部依赖**：TapeOut 工厂、电路合约、PoD 未开源，官方矿机市场、Firsto 买单和签名卖单 V2 可升级。`PoDReader` 按字段位置读取，PoD 一旦升级布局，资格判断会出错。主网部署当天建议再跑一次 `PoDWordsProbe`。
- **I-5 文档不一致**：`AUDIT.md` 第 20 行仍写"Current tag: v2.0-rc10"；第 3、5.8 节和 K10 关于报价限幅的表述（H-1）；第 3 节关于哨兵提前退出"只在冷静期内"（M-1）。修代码时一并更新，避免正式审计方按文档判断。

### 运维风险（项目方）

- **O-1 运营私钥是热钱包**：机器人服务器上的运营私钥是 H-1、M-3 的主要入口。建议：报价用单独的私钥；服务器最小权限、私钥文件加密、只开必要端口；手续费 Safe 准备好"换运营地址"的预签名流程。
- **O-2 VRF 订阅归个人钱包**：转给多签 Safe；订阅余额低于阈值自动告警。
- **O-3 测试网私钥明文**：`contracts/.env.testnet` 里有测试网部署私钥和玩家助记词（已被 `.gitignore` 排除，权限 600）。确认这两组密钥从未、也不会在主网使用；主网部署按现有脚本走硬件钱包 / keystore。
- **O-4 监控告警**：报价单次变动超过 5%、停报超过 2 小时、`postFloor` 变动、哨兵触发（`SentinelNoted`）、模板提议（`ImplementationProposed`）、VRF 请求挂起超过 1 小时、月局治理开启投票（`VoteOpened`），都应推送到 Telegram。

## 三、核对过、没有发现问题的部分

- **抽签与开奖**：`EjectionTree` 的出局权重 S − wⱼ 和二进制下降查找、最大值线段树、`PrizeDraw` 5 次按投入抽取；只接受最新请求、过期回调不回滚；开奖等待期间锁定持仓转让，没法抢跑随机数。
- **记账守恒**：标准局 `_allocate` / `_potEntitlement` / 转让结转、月局 `_returnCapital` / `_shareIncome` / 溢价分成，`liabilities` 与余额的关系；招募失败的退款与入场费精确匹配。
- **权限**：所有只认工厂、卖矿合约、治理合约、持仓凭证、随机数源、分账合约的入口都有检查；运营地址 3 天兜底逻辑一致。
- **MarketTrader**：闪电兑换回调只认指定池子和进行中的模式；卖出路径主板总是先按公式价收到 BEM，操纵 AMM 价格只会让操纵者自己吃亏；收货检查完整。
- **MachineLister / ListingVault**：EIP-1271 只认登记的 Firsto 摘要（带域分隔，不能跨协议重放）；旧单改价后摘要立即作废；任何平台低于成交时公式价都会整笔回滚。
- **PositionExchange**：卖单随持有人、持仓版本号、局交易版本号、授权变化自动失效；买单托管资金与 `totalEscrow` 一致。
- **GenesisSplitter / TWAP**：分账不变量、拒收记账、回购限额与间隔；TickMath 常量与 Uniswap V3 一致。
- **模板时间锁**：验证了"提议模板时构造函数能否冒用工厂身份"——不能（构造函数里发出的调用身份是新合约自己），这一疑点已排除。
