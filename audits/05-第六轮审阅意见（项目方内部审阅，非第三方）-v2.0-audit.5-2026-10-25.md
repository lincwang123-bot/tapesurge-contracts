## 一、总体意见

**合约：没有发现新的问题。G-1 修复有效，`v2.0-audit.5` 可以按计划部署。** 本轮的新发现都在机器人一侧，不影响明天的部署交易，也不需要改合约、重新打包。

- **G-1 已修好**：报过价之后，报价无效一律暂停收购，不再退回默认曲线；开局前必须报过价。两种局用的是同一个报价合约（`TapeSurgeDefaults` 里两种局的 `priceFeed` 都是同一个地址），所以 `startGenesis` 的检查同时覆盖标准局和月局。开局之后 `updatedAt` 不可能再回到 0，**已开出的局实际用不到默认曲线**。
- **G-2 已修好**：机器人报卖一前，先在链上模拟购买每条挂单。用今晚的实时数据验证，这个修复确实有用：Firsto 接口里**最便宜的那条挂单（#17739）现在根本买不到**，模拟购买会回滚，机器人正确地跳过了它。
- **新发现 R-1（中，机器人）**：买一取自 Firsto 统一买单，但没有在链上核对，而且现在买单很少。买一中位数靠两张各只有 0.5 BNB 的小买单撑着。其中任何一张撤单或过期，买一就会从 8.5 跌到 5.5（−35%）。这会触发 24 小时 15% 检查，**整个报价暂停**，等项目方人工确认。暂停超过 3 小时，两种局的矿机买卖都会停下。
  - **建议在开局前修好**。开局最早在铸满 10,000 颗或满 7 天时，修复不需要改合约，也不影响明天的部署。
- **主网只读核对全部符合预期**：部署钱包 nonce 3、余额够；VRF 订阅的所有者、consumer、余额都对；15 个预测地址独立重算后全部一致，而且都还没有代码。

剩余风险仍然集中在已经披露的信任假设上，和上一轮相同：运营地址的定价权、手续费 Safe 对新局模板的控制、TapeOut / PoD 未开源且可升级、外部市场可升级。**正式审计公司的审计仍然没有做**，白皮书里已经写明。

### G-1 复核细节

- `buyQuote` 现在的逻辑：`updatedAt == 0` 时用默认曲线；否则 `!fresh()` 时返回 0。"过期、追价中、运营地址为 0、停运"这四种情况都会让 `fresh()` 为假，所以都暂停收购。
- `startGenesis` 检查的是 `_boardConfig.priceFeed.updatedAt() != 0`。月局只能经 `startGenesis → openFirst` 开出第一块，之后由 `MonthFactory` 自动开，**两条路径都在报过价之后**。
- 第一次报价用 `postCatchUp`，或者开局时报价已经过期，都不会退回曲线：`updatedAt != 0`，收购只会暂停。
- 暂停收购不会让资金卡住：
  - 标准局首轮一台没买到时，`expire()` 按保底规则退款（入场费 1% 已经在开局时转给手续费 Safe，不退）；
  - 月局准备期没买到时，结算时原样退还。
- 卖出一侧不变：停运后月局按成本价可买，清算计划价在报价无效时暂停。
- 测试夹具说明：`Fixture._startGenesis` 开局后用 `vm.store` 把报价合约的 0、1、2、6 号槽清零，也就是 `bid`、`ask`、`updatedAt`、`liveAt`。本轮用 `forge inspect` 核对过存储布局，槽位正确。这样大部分旧测试（30 个文件、80 处）仍然走默认曲线，这个状态在生产中不会出现；按报价收购的路径由 17 个测试文件覆盖（见 R-6）。

## 三、本轮新发现

### R-1（中，机器人）：买一没有链上核对，买单太少，单张撤单就能让整个报价暂停

**位置**：
- `bot/src/market.js` 的 `firstoBid()`：取最高 3 张买单的中位数，只要求 `state === 'active'`、剩余预算 ≥ 0.1 BNB；
- `bot/src/tasks/pricefeed.js` 的 `dayGuard()`：买一、卖一任何一侧 24 小时内变动超过 15%，就暂停整个报价。

**问题**：

1. 今晚的真实买单（区块约 129,709,275）：

   | 买单 | 日产能价（BNB） | 剩余预算（BNB） |
   |---|---|---|
   | #1269 | 8.51 | 0.5 |
   | #1268 | 8.50 | 0.5 |
   | #1273 | 5.52 | 10 |
   | #1270 | 5.50 | 10 |
   | #910 | 4.00 | 20 |

   机器人算出的买一 = 8.50。**这个价完全由两张各 0.5 BNB 的小买单决定**：其中一张撤单、过期或被吃掉，中位数就变成 5.50（−35%）。

2. `dayGuard` 发现买一比 24 小时内的最高价低了 35%，就**暂停整个报价**（卖一也不报了），直到项目方运行 `feed-confirm.mjs`。之后：
   - 3 小时后报价过期，两种局的矿机买卖全部暂停；
   - 如果 7 天都没人确认，报价停运，月局结算中的矿机任何人都可以按成本价买。
   - 已用真实数据复现，见附录的 `bid-drop.mjs`。输出：`买一比 24 小时内最高价低了 35.29%`，`ok: false`。
3. **0.1 BNB 的门槛太低**：一台 10 算力的矿机按 8.5 的价格要约 0.38 BNB。0.5 BNB 的买单吃掉一台后只剩约 0.12 BNB，再也买不下任何一台合格矿机，但仍然被计入中位数。复现脚本里把 #1269 改成剩 0.12 BNB，买一仍是 8.5。
4. **往上抬也很便宜**：挂几张每张 0.1 BNB 预算（可以撤回）、价格接近卖一的买单，就能把买一抬到接近卖一。影响有上限，因为机器人会把买一压到卖一以下，主板收购价也不会超过卖一。但会出现这些结果：
   - 主板一开始就按卖一收购，本来应该从买一 × 1.005 每小时往上涨，这段约 10% 的价差没了；
   - 月局清算计划的底价（买一 × 95%）和标准局拍卖起价跟着变高；
   - 抬高超过 15% 同样会触发暂停，攻击者成本只有约 0.2 BNB（可以撤回）。

**影响**：资金不会被直接拿走，主要是"报价被迫暂停"的可用性问题，外加有上限的价差损失。但按现在的买单结构，**上线头几天很可能自然触发**（小买单过期或撤单），每次都要人工确认。

**建议**（只改机器人，不改合约）：

1. 只计入剩余预算 ≥ "参考矿机整台价"的买单（`refCostWei`，也就是卖一中位数那台矿机），并按出价人去重。
2. 和卖一一样做链上核对：读统一买单合约里这张单的状态和剩余预算；或者用一台真实矿机模拟一次 `0x4c67242f`，确认它真能成交。
3. 买一单独处理大幅变动：**买一变动大时不要暂停整个报价**，改用已有的"卖一 × (1 − 9%)"估算（`FEED_NO_BID_SPREAD_BPS`），同时报警。只在卖一 24 小时内变动超过 15% 时暂停。
4. 开局前（铸满 10,000 颗或满 7 天前）修好，并在主网机器人上空跑一轮确认。

### R-2（低，机器人）：卖一候选没有按主板的收购条件过滤

**位置**：`bot/src/askcheck.js` 的 `askCandidates()` 和 `verifiedAskRows()`。

**问题**：参与卖一中位数的候选没有过滤以下几类：
- 算力 10–300 以外的矿机：今晚的数据里就有一台 7 算力的挂单，主板不能收它；
- 快到期的单：`parseAsks` 要求至少还剩 10 分钟，这里没有要求；
- 机器人不支持的挂单来源：今晚有一条 `venue: official` 的挂单。它会被记成 "unsupported listing"，占用 20 次核对名额中的一次，还会让这个卖家本小时不再参与。

现在的数据下影响很小。但卖一应该反映"主板能买到的矿机"的价格。另外，攻击者如果用十几个钱包、每个挂一条买不到的低价单，可以耗光 20 次核对名额，让机器人凑不够 3 个卖家（成本是十几台已验证矿机，不低）。

**建议**：
- 先按主板收购条件过滤，再计入：算力 10–300、剩余有效期 ≥ 10 分钟、挂单类型受支持；
- 不支持的挂单类型直接跳过，不占核对名额；
- 适当提高 `maxChecks`。`eth_call` 很便宜，现在核对 4 条就够了。

### R-3（低，上线脚本）：两处可能误导或漏检的小问题

1. **提示过时**：`contracts/script/mainnet.sh deploy` 广播成功后最后一行打印：

   ```
   NEXT: add the VRF adapter as a consumer of subscription …
   ```

   这是旧提示。G-4 之后，部署前已经强制要求适配器是 consumer（今晚链上核对也确认了）。部署当晚看到这句话，部署的人可能以为还要去 Chainlink 页面操作。建议改成"运行 `bash 上线/部署后收尾.sh`"。

2. **代码核对会漏掉两种改动**：`上线/2-明天一键部署.sh` 用 `git diff --quiet v2.0-audit.5 -- src script foundry.toml remappings.txt` 核对代码，但：
   - `git diff` 不看**未跟踪的新文件**；
   - 没有包括 `lib/`（OpenZeppelin、forge-std）。

   建议加一条：

   ```bash
   git status --porcelain --untracked-files=all -- src script lib foundry.toml remappings.txt
   ```

   输出为空才继续。

附带说明（不算问题）：预留铸造是第 16 笔、也是最后一笔。万一在它之前创世晶体管已经被公开铸完，这一笔会回滚，`mainnet.sh` 会在写 `deployments/56.json` 之前退出（`pipefail`）。此时 15 个合约已经部署完，`56.pending.json` 还在，按操作卡"先停下来"处理即可。

### R-4（信息，合约）：以后换报价合约的新模板会重新碰到"从没报过价"

`startGenesis` 的检查只在开局时做一次。以后如果经 7 天时间锁换上一个**使用新报价合约**的模板，新报价合约的 `updatedAt == 0`：新模板开出的局在机器人报第一次价之前，仍会按默认曲线收购。现在不受影响。

**建议**：
- 写进审计说明和模板升级流程：新报价合约必须先报过价再让模板生效；
- 或者在新模板里把"从没报过价"也当成暂停。
